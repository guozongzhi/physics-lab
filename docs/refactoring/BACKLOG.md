## 2. 业务回归矩阵

以下每行都要覆盖正常路径、拒绝路径和刷新后结果。UI 控件测试只用于组件行为，业务正确性主要在服务端集成测试和完整流程中确认。

| 场景 | 核心断言 | 验证层 |
|---|---|---|
| 登录/刷新/登出/401 | 角色入口正确；旧用户数据清理；失败登录不进入业务页 | 会话单测 + E2E |
| 学生 A 换学生 B；教师换学生 | B 不能看到 A 的草稿/流水/题目缓存；迟到响应被丢弃 | 异步单测 + E2E |
| 在线部分 API 失败 | 失败资源显示错误/重试，不用演示数据和默认 0 冒充结果 | 查询集成 + E2E |
| URL 直达/刷新/404 | 全部登记路由可达；Shell 只一层；无路由链接自动检查 | 路由测试 + E2E |
| 班级/小组管理 | 无组、满组、跨班、组长变化、删除依赖处理；写失败不改变最终事实 | 服务端 + E2E |
| 题库创作/审核/导入 | 状态转换、教师范围、反馈、去重；跨浏览器一致；空库不自动恢复示例 | 服务端 + E2E |
| 测验/挑战 | 单选/多选/判断评分；草稿恢复；重复交卷；窗口关闭后的合法结算 | 服务端 + E2E |
| 安全练习/指派/项目安全 | 练习不能冒充指派通过；项目准入来自合法记录；跨班访问拒绝 | 服务端 + E2E |
| 项目状态与完成 | 归属权限；合法状态变化；重复与并发完成只发一次奖励 | 事务测试 + E2E |
| 招募生命周期 | 发布押金、投标、分配、完成/部分/失败、余额与流水一致 | 服务端 + E2E |
| 转账/教师调币 | 余额不足、非正整数、同组、权限、超时确认、并发不超扣 | 服务端并发 + E2E |
| 成果审批 | 未审核可见性、拒绝理由、重复审核、奖励一次 | 服务端 + E2E |
| 首页/教师指标/排名 | 本人、本组、班级、时间窗口径明确；筛选影响 KPI 与图表一致 | 选择器单测 + 页面集成 |
| 日期和到期窗口 | naive UTC、Z、offset、跨日/年、非法输入、UTC 与本地显示正确 | 纯函数单测 + 服务端 |
| 弹窗/表单/移动导航 | 键盘、焦点、滚动锁、多弹窗、关闭恢复、提交错误与 pending | 组件测试 + 浏览器 |
| 旧库迁移/恢复 | 表/索引/约束、计数、关键金额总量、流水引用保持；失败可恢复 | 匿名 DB 副本演练 |

## 3. 门禁与证据

1. 每个提交：check、受影响模块测试、迁移模块 lint；涉及后端业务规则跑完整后端测试。全仓 lint 记录基线且不增加，最终清零。
2. 每个业务域完成：build、三角色相关流程、API 失败/超时/权限验证、数据刷新对齐，以及原路由直接访问。
3. 数据迁移：备份恢复 + 空库升级 + 匿名旧库升级；金额/流水关键不变量核对。不能只以 migration 命令退出码为依据。
4. UI 验收：截图注明视口/角色/数据场景/主题；比较层级、溢出、焦点和可读性，不接受仅凭可编译宣称 UI 完成。
5. 架构验收：import 边界、循环依赖、生产到 demo 的依赖、旧入口引用数量、同一资源的读写归属。
6. 性能验收：保存相同夹具和网络条件下的首屏、页面切换与写入体验；记录 build 主包 gzip、页面 chunk、API 请求数量。PLAN 中的包体指标是目标，当前没有用户端性能测量。

## 4. 风险与处理

| 风险 | 应对 |
|---|---|
| 重构中丢弃浏览器本地题库 | 先导出与核对，服务端迁移成功后才撤旧入口，保留原始副本 |
| 新旧 store/query 互相覆盖 | 按资源迁移，统一 ownership 表；每个资源只有一个有效写入口 |
| 一次搬目录导致难定位行为回归 | 纯移动与行为更改分提交，旧路径短期转发，变更集保持小 |
| 权限收紧使现有教师不可操作 | 明确班级授权迁移与管理员配置入口，用匿名既有场景演练 |
| Alembic 接管未知结构或启动竞态 | 先检查结构与副本演练，迁移单独执行，不让多实例自行 ALTER |
| 并发测试在 SQLite 失真 | 使用多连接文件型临时库，不只依赖单连接内存库；验证实际失败/回滚行为 |
| 把主题统一变成过度装饰 | 学生页突出下一步，教师页突出处理效率；视觉目标与完成任务同时验收 |
| 工期受测试/数据补齐影响 | 阶段 0 后重估；优先交付会话/写入正确性、单布局和首页样板 |
